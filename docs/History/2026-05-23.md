# Work log — 2026-05-23 (v1.3.0: selective termination + orphan analysis + Round 2 security hardening)

> v1.3.0 — active session preservation + orphan identification + UAC injection / whitelist bypass security patch.
> At user request, switch the v1.2.x "terminate all" strategy to "selective termination".

## Motivation

### Actual patterns found in user environments

Measured on DDR4 64 GB / Ryzen 5 5600G / Windows 10 LTSC:

| Item | VS Code (active 9) | Antigravity (active 7) |
|---|---|---|
| Total processes | 23 | 21 |
| Total memory | 4,815 MB | 4,587 MB |
| **claude.exe count** | **13** | **10** |
| **Estimated excess (orphans)** | **4** | **3** |
| GPU processes | 178 MB | **447 MB (+151%)** |
| Handles/proc | 467 | **758 (+62%)** |

Key findings:
1. **claude.exe is the real memory hog** — average 350 MB × 23 = **8 GB**. Grandchild node.exe (MCP server, 60 MB × 22) is secondary.
2. **Active IDE session count and claude.exe count do not match** — Child claude.exe does not terminate even when the IDE closes a chat tab. This is due to Windows `TerminateProcess`'s non-cascade limitation + the IDE extension's short cleanup timeout.
3. **60 GB leak scenario verified** — 350 MB × 150 + node 60 MB × 150 + IDE = ~66 GB → matches user reports.

### Limitations of v1.2.x

v1.2.x **terminates all matching processes at once** — sessions the user is working in also disappear.
User request: **"preserve active sessions and remove only unnecessary ones"**.

### P0: 3 selective termination options

| Option | Behavior | Use case |
|---|---|---|
| `-KeepPids "1234,5678"` | Preserve specified PIDs, terminate the rest | Active PIDs already known |
| `-Interactive` | Prompt to preserve each PID before termination | PIDs unknown, want to decide at once |
| `-OrphansOnly` | Only claude.exe/node.exe whose parent IDE is dead | Safe mode, most conservative |

Internal structure:
- `ConvertFrom-KeepPidsString` (line 343): CSV string → safe `[uint32[]]` parser.
- `Test-IsClaudeOrphan` (line 332): detects both parent PID death + PID reuse cases.
- Extended the `Get-TargetProcesses` signature (line 359): `-ExcludePids` + `-OnlyOrphans` parameters.
- Updated UAC round-trip argument passing (line 114-125).

### P2: orphan analysis (`-Diagnose` enhancements)

`Show-ZombieAnalysis` (line 612) — groups `claude.exe` by `ParentProcessId`:
- **[OK]**: Parent is an IDE/legitimate spawner (`Code|Antigravity|claude|cursor|windsurf|cmd|pwsh|bash|...`) → active
- **[DEAD]**: Parent PID is not enumerated → confirmed orphan
- **[REUSED]**: Parent PID exists but is not an IDE (PID reuse) → orphan

At the end of the summary, print a "safe termination command" for copying:
```
[!] Confirmed orphans: N / M MB
    → Safe termination:  .\MemoryReset.ps1 -OrphansOnly
```

### Round 2: security review (general-purpose agent, adversarial)
**3 P0 security vulnerabilities found** — decided to hold the commit:

1. **`-KeepPids` UAC injection** — Passed to the elevated PowerShell command line without input validation.
   PoC: `-KeepPids '1234"; Start-Process calc.exe; #'` → arbitrary code execution possible.
2. **Unanchored whitelist path** — `\\\.vscode\\extensions\\...` is user-writable
   `C:\evil\.vscode\extensions\anthropic.claude-code-evil\claude.exe` also matches → can trigger termination of arbitrary processes as admin.
3. **Trusting the CLI signature alone** — matches on `--output-format stream-json` alone → spoofable.

P1 4 cases: `ConvertFrom-KeepPidsString` overflow / unwrap, insufficient spawner whitelist in `Test-IsClaudeOrphan`, etc.

## Round 2 patch (Phase C — hardening)

### P0 security

| Patch | Location | Behavior |
|---|---|---|
| KeepPids input validation | line 73-80 | Enforce regex `^[\d,\s]*$` — **before** UAC elevation. On violation exit 1. |
| %USERPROFILE% anchor | line 380-395 | prefix-match IDE extension paths with `[String]::StartsWith(prefix, OrdinalIgnoreCase)`. Drop regex substring matching. |
| CLI signature AND-gate | line 397 | Stop trusting `--output-format stream-json` alone → combine with path signals using AND. |

### P1 hardening

- `ConvertFrom-KeepPidsString` (line 343-360): overflow-safe with `[uint32]::TryParse`, prevent single-element unwrap with `,$valid` array-wrap, Yellow warning for invalid entries.
- `Test-IsClaudeOrphan` (line 332-340): Add `cmd|pwsh|powershell|bash|wsl|explorer|conhost` to the parent whitelist — protects normal cases where node.exe is spawned by npm/terminal.
- Wrap all 3 `Get-TargetProcesses` calls in the Main flow with `@()` — strict-mode safe.
- Print a Yellow warning when `-Interactive` + `-DryRun` are combined.

## Known limitations (v1.4 deferred)

1. **Graceful-kill race window**: The target PID could be reassigned by the OS during the 8-second graceful wait.
   `taskkill` requires rechecking PID identity (process name + start-time) immediately before it. Design limitation present since v1.0+.
2. **v1.3 options not exposed in tray menu**: `-KeepPids` / `-Interactive` / `-OrphansOnly` are CLI only.
   Tray integration in v1.4.
3. **`Where-Object { return $false }` antipattern**: Idiom existing since v1.2. Behavior is correct but may break during a future `if/else` refactor. Separate PR.
