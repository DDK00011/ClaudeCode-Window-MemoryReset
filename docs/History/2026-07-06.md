# 2026-07-06 — 진행 중인 Codex 세션 보존

## 문제
- MemoryReset 이 진행 중인 Codex 세션을 정리 대상에 포함해 종료할 수 있었음.
- 특히 VS Code 에서 실행된 Codex CLI 는 기존 `codex.exe` / `node_repl.exe` 화이트리스트에 직접 매칭되어 종료 대상이 됐고, Antigravity 쪽 Codex 는 실행 경로/부모 구조 차이로 우연히 살아남는 상태였음.

## 근본 원인
- `Get-TargetProcesses` 가 Claude/Antigravity 회수 도구 안에 Codex CLI 수집 로직을 직접 갖고 있었음.
- `-IncludeDescendants` 및 최종 `taskkill /T` 경로에서는 Codex 가 직접 대상이 아니어도 부모 트리 종료로 같이 죽을 수 있었음.

## 변경
- Codex 를 정리 대상에서 완전히 빼는 방식은 요구와 맞지 않아 폐기.
- `Test-IsCodexProcess`, `Get-CodexRootPids` 추가:
  - `codex.exe`
  - `node_repl.exe`
  - `@openai/codex`
  - `OpenAI\Codex`
- Codex CLI root 는 다시 정리 대상에 포함.
- `Update-ActivityState` 가 Codex root 만 보지 않고 Codex 프로세스 트리 전체의 CPU/I/O 카운터를 합산.
- `-IdleOnly` 후보 산출 직전과 실제 종료 직전에 `Update-ActivityState` 를 다시 호출해 오래된 idle 상태로 진행 중인 Codex 를 죽이는 경로 차단.
- `Stop-TargetProcesses` 는 추적 이력이 없거나 아직 idle 로 증명되지 않은 Codex 트리만 `CloseMainWindow` 전부터 스킵.
- Codex `node.exe` root 가 Claude `node.exe` orphan 으로 오분류되지 않도록 `-OrphansOnly` / `Get-ReclaimCandidates` 에서 Codex 를 orphan 즉시 종료 경로에서 제외.
- `Test-Patterns.ps1` 에 Codex active guard, 트리 CPU/I/O 추적, orphan 제외, 빈 배열 double-wrap 회귀 체크 추가.
