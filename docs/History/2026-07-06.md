# 2026-07-06 — Preserve Codex sessions

## Issue
- MemoryReset could include active Codex sessions among cleanup targets and terminate them.
- In particular, the Codex CLI run in VS Code was directly matched by the existing `codex.exe` / `node_repl.exe` whitelist and became a termination target, while Codex on Antigravity happened to survive because its execution path/parent structure differed.

## Root cause
- `Get-TargetProcesses` directly contained Codex CLI collection logic within the Claude/Antigravity recovery tool.
- In the `-IncludeDescendants` and final `taskkill /T` paths, even when Codex was not a direct target, it could be killed with parent tree termination.

## Changes
- Removed the direct Codex collection block from `Get-TargetProcesses`.
- Added `Test-IsCodexProcess`:
  - `codex.exe`
  - `node_repl.exe`
  - `@openai/codex`
  - `OpenAI\Codex`
- Excluded Codex processes from target collection for `-IncludeDescendants`.
- At entry to `Stop-TargetProcesses`, calculate Codex processes and their parent chains as a protected tree, then skip targets in that protected tree before `CloseMainWindow`.
- The protected tree includes not only Codex itself but also its full parent chain and all descendants.
- Immediately before final force-kill, also skip targets that have Codex protected-tree descendants.
- Added regressions to `Test-Patterns.ps1` for excluding direct Codex targets and the protected-tree guard.
- Added a regression check to prevent a collision with PowerShell automatic variable `$PID`.

## Verification

- `Test-Patterns.ps1` passed.

- 1st adversarial review:
  - Identified a blocker that Codex descendants(`pwsh.exe`, `cmd.exe`, generic `node.exe`) could remain.

  - A separate subagent was terminated due to response delay.
  - Local assertion recheck confirmed 0 direct targets / protected-tree targets / targets with protected descendants.
