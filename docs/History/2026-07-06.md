# 2026-07-06 — Codex 세션 보존

## 문제
- MemoryReset 이 진행 중인 Codex 세션을 정리 대상에 포함해 종료할 수 있었음.
- 특히 VS Code 에서 실행된 Codex CLI 는 기존 `codex.exe` / `node_repl.exe` 화이트리스트에 직접 매칭되어 종료 대상이 됐고, Antigravity 쪽 Codex 는 실행 경로/부모 구조 차이로 우연히 살아남는 상태였음.

## 근본 원인
- `Get-TargetProcesses` 가 Claude/Antigravity 회수 도구 안에 Codex CLI 수집 로직을 직접 갖고 있었음.
- `-IncludeDescendants` 및 최종 `taskkill /T` 경로에서는 Codex 가 직접 대상이 아니어도 부모 트리 종료로 같이 죽을 수 있었음.

## 변경
- `Get-TargetProcesses` 에서 Codex 직접 수집 블록 제거.
- `Test-IsCodexProcess` 추가:
  - `codex.exe`
  - `node_repl.exe`
  - `@openai/codex`
  - `OpenAI\Codex`
- `-IncludeDescendants` 대상 수집에서 Codex 프로세스를 제외.
- `Stop-TargetProcesses` 진입 시 Codex 프로세스와 그 부모 체인을 보호 트리로 계산하고, 보호 트리에 포함된 대상은 `CloseMainWindow` 전부터 스킵.
- 보호 트리는 Codex 본체뿐 아니라 부모 체인과 자손 전체를 포함.
- 최종 강제 종료 직전에도 Codex 보호 트리 자손이 있는 대상은 스킵.
- `Test-Patterns.ps1` 에 Codex 직접 대상 제외 및 보호 트리 가드 회귀 체크 추가.
- PowerShell 자동 변수 `$PID` 충돌 방지를 회귀 체크에 추가.
