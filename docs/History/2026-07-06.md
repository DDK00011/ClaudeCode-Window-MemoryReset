# 2026-07-06 — 진행 중인 Codex 세션 보존

## 문제
- MemoryReset 이 진행 중인 Codex 세션을 정리 대상에 포함해 종료할 수 있었음.
- 특히 VS Code 에서 실행된 Codex CLI 는 기존 `codex.exe` / `node_repl.exe` 화이트리스트에 직접 매칭되어 종료 대상이 됐고, Antigravity 쪽 Codex 는 실행 경로/부모 구조 차이로 우연히 살아남는 상태였음.

## 근본 원인
- `Get-TargetProcesses` 가 Claude/Antigravity 회수 도구 안에 Codex CLI 수집 로직을 직접 갖고 있었음.
- `-IncludeDescendants` 및 최종 `taskkill /T` 경로에서는 Codex 가 직접 대상이 아니어도 부모 트리 종료로 같이 죽을 수 있었음.

## 변경
- Codex 를 정리 대상에서 완전히 빼는 방식은 요구와 맞지 않아 폐기.
- `Test-IsCodexProcess`, `Get-CodexRootPids` 추가:
  - `codex.exe`
  - `node_repl.exe`
  - `@openai/codex`
  - `OpenAI\Codex`
- Codex CLI root 는 다시 정리 대상에 포함.
- `Update-ActivityState` 가 Codex root 만 보지 않고 Codex 프로세스 트리 전체의 CPU 카운터를 합산하고, I/O 카운터는 진단값으로 기록.
- `-IdleOnly` 후보 산출 직전과 실제 종료 직전에 `Update-ActivityState` 를 다시 호출해 오래된 idle 상태로 진행 중인 Codex 를 죽이는 경로 차단.
- `Stop-TargetProcesses` 는 추적 이력이 없거나 아직 idle 로 증명되지 않은 Codex 트리만 `CloseMainWindow` 전부터 스킵.
- Codex `node.exe` root 가 Claude `node.exe` orphan 으로 오분류되지 않도록 `-OrphansOnly` / `Get-ReclaimCandidates` 에서 Codex 를 orphan 즉시 종료 경로에서 제외.
- `Test-Patterns.ps1` 에 Codex active guard, 트리 CPU 추적, orphan 제외, 빈 배열 double-wrap 회귀 체크 추가.

## 추가 수정 — 절전 후 idle Codex 미회수

### 문제
- 5시간 이상 경과하고 작업이 끝난 Codex 세션이 `idleMinutes` 조건을 충족했는데도 정리 후보가 되지 않음.
- 중간에 절전/재개가 있었고, 재개 후 `TrackActivity` tick 에서 Codex `lastActiveAt` 이 현재 시각으로 밀리며 후보 수가 0으로 돌아감.

### 근본 원인
- 앞선 Codex 보호 보완에서 Codex 트리의 I/O 카운터 증가까지 `lastActiveAt` 갱신 조건으로 사용함.
- 절전 재개, IPC, 로그, 백그라운드 파일 핸들 정리 같은 I/O-only 변화가 실제 작업 진행이 아닌데도 "활동"으로 기록되어 idle 시간이 리셋됨.

### 변경
- `Update-ActivityState` 는 Codex 트리 CPU delta 만 활동 판정에 사용.
- `lastIoOps` / `lastIoBytes` 는 계속 기록하지만 진단용으로만 유지하고 `lastActiveAt` 을 갱신하지 않음.
- 기존 버전에서 이미 I/O-only 로 오염된 state 는 `activityModel` 이 없고 `lastActiveAt == lastSeenAt` 이며 CPU율이 임계 미만인 경우에만 보수적으로 보정.
- 보정 여부가 애매한 legacy state 는 `activityModel` 을 찍지 않아 다음 tick 에서 새 CPU 모델로 다시 관측할 수 있게 함.
- active Codex 자손을 가진 부모 프로세스는 `CloseMainWindow` 전부터 제외.
- force `taskkill /T` 직전에는 프로세스 스냅샷과 active Codex 보호 PID를 다시 계산.
- `activity-state.json` 은 임시 파일에 완성 JSON을 쓴 뒤 교체하고, 읽기는 1회 재시도해 동시 스케줄 실행 중 부분 JSON으로 state가 비는 문제를 줄임.

### 구조 판단
- 임시 예외처리 아님. 종료 대상/후보/최종 종료 가드가 모두 공유하는 `Update-ActivityState` 의 활동 모델을 수정한 근본 해결.
- `Stop-TargetProcesses` 의 Codex 보호 가드는 유지되어, CPU 활동이 새로 관측된 세션은 종료 직전에도 보존됨.

### 추가 적대적 검토 반영
- 1차 검토: legacy 보정 조건이 너무 좁고, 보정 실패 state 에 `activityModel` 을 찍으면 이후 보정 기회가 사라진다는 blocker 확인 후 수정.
- 2차 검토: active Codex 자손 보호가 force 단계에만 있어 graceful close 로 먼저 닫힐 수 있다는 blocker 확인 후 `CloseMainWindow` 이전 필터로 이동.
- 2차 검토: `activity-state.json` 직쓰기 중 읽기 실패 시 빈 state 로 진행할 수 있다는 blocker 확인 후 retry + temp replace 저장으로 보완.
- 작업 중 09:30 자동 `TrackActivity` 가 중간 버전으로 한 번 실행되어 로컬 `activity-state.json` 이 빈 state 로 갱신됨. 해당 파일은 git 제외 런타임 파일이며, 이후 tick 부터 새 이력이 쌓임.

## 추가 수정 — 주요 실행 파일 로그

### 문제
- hidden scheduled cleanup 은 콘솔 출력이 보존되지 않아 `CloseMainWindow`, Codex 보호 skip, `taskkill` 결과를 사후 확인할 수 없었음.
- 기존 `tracker.log` 는 후보 수, `recovery-history.csv` 는 종료 총량만 기록해 `ProcessesKilled=52` 같은 사건의 개별 PID/분류/idle-orphan 이유가 남지 않았음.

### 변경
- `Write-RunLog` 추가: `memoryreset.log` 에 주요 실행 흐름을 append.
- main cleanup 실행마다 모드, raw/final target count, target PID/PPID/name/category/WorkingSet/start time/path, idle/orphan 이유를 기록.
- `Stop-TargetProcesses` 에 Codex guard skip, `CloseMainWindow`, no-window, wait, survivor count, `taskkill` 성공/이미 종료/실패 결과 로그를 추가.
- 회수 완료 시 mode, target count, before/after free MB, recovered MB, elapsed sec 를 기록.

### 구조 판단
- 임시방편 아님. scheduled task 의 stdout 을 새로 캡처하지 않고, 실제 종료 판단이 일어나는 공유 경로에 파일 로그를 직접 남겨 원인 추적 공백을 막음.
- `memoryreset.log` 는 기존 `.gitignore` 의 `*.log` 보호를 그대로 사용하므로 개인 런타임 기록은 커밋되지 않음.
