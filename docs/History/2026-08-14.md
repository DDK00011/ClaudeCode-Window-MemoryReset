# 2026-08-14 — Prevent Accidental Claude Termination During Work

## Issue
- The `ClaudeCodeMemoryCleanup` scheduled task misclassified normal VS Code Claude PID 42856 at 2026-08-13 17:12:46 as `idle=True`, `orphan=False`.
- Claude received an API response at the same time and was running Bash/WSL verification commands, but was terminated by `taskkill /F /T` at 17:12:55.
- 17:15:18 The user resumed the same session ID with `continue`.

## Root cause
- `Update-ActivityState` aggregates process-tree CPU only for Codex, while for Claude it observes only root CPU, missing child Bash/WSL/tool work.
- Even after updating activity state after candidate selection and immediately before force kill, `Stop-TargetProcesses` protection targets were exclusive to Codex.
- The force stage checked only descendants of protected PIDs, so it could also miss cases where the waiting root itself became active.
- If the cumulative tree CPU total decreased due to child-process termination/replacement, an additional path could clip delta to 0 and miss activity.

## Design Decision
- Not a temporary workaround that changes the threshold or schedule.
- A root fix that commonly observes the real Claude/Codex process trees producing activity, then revalidates activity twice after selection in the shared termination path of `-IdleOnly`.
- Manual normal/full cleanup keeps the existing meaning that it also terminates working Claude, and common Claude protection applies only to `-ProtectActive:$IdleOnly`.

## Changes
- Aggregate total descendant CPU/I/O for every Claude/Codex target root.
- Generalize `Get-ActiveCodexProtectedPids` to `Get-ActiveProtectedPids`:
  - Keep existing active Codex protection.
  - Also protect Claude roots targeted by `-IdleOnly`.
  - Preserve fail-closed if the creation times of state and the current root differ or cannot be checked.
- `Stop-TargetProcesses` checks the intersection of root+descendant protected PIDs before graceful close and immediately before force kill.
- Snapshot root identity and tree composition once more immediately before force kill, preserving on changes.
- Treat a decrease in cumulative tree CPU total as child termination/replacement activity and update `lastActiveAt`.
- Add the following runtime verification to `Test-Patterns.ps1`:
  - Active protection when Claude descendant CPU increases or total decreases.
  - No `taskkill` call when root or descendant becomes active immediately before pre-close/force.
  - No `taskkill` call when tree changes immediately before force.
  - A failure counter where all `[FAIL]` assertions return exit code 1.

## Adversarial Review Follow-up
- Logic review found the path where CPU total decreases from child-process churn and a PID/tree snapshot race, adding fail-closed safeguards.
- Test review found that static regex alone could pass even if it bypassed the protection branch, and that `[FAIL]` exited 0.
- Added four activation races and tree-change checks that mock-run actual `Stop-TargetProcesses`, and changed the overall failure gate to a non-zero exit.
