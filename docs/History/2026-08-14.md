# 2026-08-14 — 작업 중 Claude 오종료 방지

## 문제
- `ClaudeCodeMemoryCleanup` 예약 작업이 2026-08-13 17:12:46에 정상 VS Code Claude PID 42856을 `idle=True`, `orphan=False`로 오판함.
- Claude는 같은 시각 API 응답을 받고 Bash/WSL 검증 명령을 실행 중이었지만 17:12:55 `taskkill /F /T`로 종료됨.
- 17:15:18 사용자가 같은 세션 ID를 `continue`로 재개함.

## 근본 원인
- `Update-ActivityState`가 Codex만 프로세스 트리 CPU를 합산하고 Claude는 root CPU만 관측해 자식 Bash/WSL/tool 작업을 놓침.
- 후보 선정 뒤와 force kill 직전에 활동 상태를 갱신해도 `Stop-TargetProcesses`의 보호 대상이 Codex 전용이었음.
- force 단계는 보호 PID의 자손만 검사해, 대기 중 root 자체가 활성화된 경우도 놓칠 수 있었음.
- 자식 프로세스 종료/교체로 트리 누적 CPU 합계가 감소하면 delta를 0으로 잘라 활동을 놓치는 추가 경로가 있었음.

## 구조 판단
- 임계값이나 예약 주기를 바꾸는 임시 회피가 아님.
- 활동을 생산하는 실제 Claude/Codex 프로세스 트리를 공통 관측하고, `-IdleOnly`의 공유 종료 경로에서 선택 후 활동을 두 번 재검증하는 근본 수정.
- 수동 일반/전체 청소는 작업 중 Claude도 종료한다는 기존 의미를 유지하고, 공통 Claude 보호는 `-ProtectActive:$IdleOnly`에만 적용함.

## 변경
- 모든 Claude/Codex target root의 전체 자손 CPU/I/O를 합산.
- `Get-ActiveCodexProtectedPids`를 `Get-ActiveProtectedPids`로 일반화:
  - 기존 active Codex 보호 유지.
  - `-IdleOnly` 대상 Claude root도 추가 보호.
  - state와 현재 root의 생성 시각이 다르거나 확인 불가하면 fail-closed 보존.
- `Stop-TargetProcesses`가 graceful close 전과 force kill 직전에 root+자손 보호 PID 교집합을 검사.
- force kill 직전 root 정체성과 트리 구성을 한 번 더 스냅샷해 변경 시 보존.
- 트리 누적 CPU 합계 감소를 자식 종료/교체 활동으로 간주해 `lastActiveAt` 갱신.
- `Test-Patterns.ps1`에 다음 실행 검증 추가:
  - Claude 자손 CPU 증가 및 합계 감소 시 active 보호.
  - pre-close/force 직전 root 또는 자손 활성화 시 `taskkill` 미호출.
  - force 직전 트리 변경 시 `taskkill` 미호출.
  - 모든 `[FAIL]` assertion이 종료 코드 1을 반환하는 failure counter.

## 적대적 검토 반영
- 논리 검토에서 자식 프로세스 churn으로 CPU 합계가 감소하는 경로와 PID/tree snapshot race를 발견해 fail-closed 보완.
- 테스트 검토에서 정적 regex만으로 보호 분기를 무력화해도 통과할 수 있고 `[FAIL]`이 exit 0인 문제를 발견함.
- 실제 `Stop-TargetProcesses`를 mock 실행하는 네 가지 활성화 race와 트리 변경 검사를 추가하고 전체 failure gate를 non-zero exit로 변경함.
