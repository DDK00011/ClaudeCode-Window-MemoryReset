# 2026-07-08 — 스케줄러 PowerShell 포커스 탈취 방지

## 문제
- `ClaudeCodeMemoryTracker` 가 30분마다 실행되며 PowerShell 콘솔이 순간적으로 뜨고, 타이핑 포커스를 끊는 증상이 있었음.
- 자동 정리 작업도 같은 방식으로 `powershell.exe` 를 직접 실행하고 있어 3시간 주기로 같은 문제가 날 수 있었음.

## 구조 판단
- 임시방편 아님.
- 원인은 MemoryReset 로직이 아니라 Windows 작업 스케줄러가 로그인 세션에서 콘솔 호스트인 `powershell.exe` 를 직접 실행하는 호출 방식.
- 따라서 추적/정리 로직은 유지하고, 스케줄러 진입점만 콘솔 없는 `wscript.exe` 래퍼로 바꾸는 것이 원인층 해결.

## 변경
- `Run-Hidden.vbs` 추가:
  - 같은 폴더의 `MemoryReset.ps1` 을 호출.
  - `WScript.Shell.Run(..., 0, True)` 로 PowerShell 창을 숨김 실행하고 종료 코드를 전달.
- `Track-Schedule.ps1`:
  - `New-ScheduledTaskAction` 실행 파일을 `powershell.exe` 에서 `wscript.exe` 로 변경.
  - 인자는 `//B //NoLogo "Run-Hidden.vbs" -TrackActivity`.
- `Cleanup-Schedule.ps1`:
  - 자동 정리도 동일하게 `wscript.exe` 래퍼 사용.
  - 인자는 `//B //NoLogo "Run-Hidden.vbs" -IdleOnly -SkipConfirmation -KeepAlive`.
- `Test-Patterns.ps1`:
  - `Run-Hidden.vbs` 존재 체크 추가.
  - 트래커/정리 스케줄 등록 스크립트가 `wscript.exe` + `Run-Hidden.vbs` 를 쓰는지 회귀 체크 추가.
- 로컬 런타임 설정:
  - git 제외 파일 `tracker-settings.json` 의 `trackIntervalMin` 을 30 → 90으로 변경.
  - `idleMinutes` 는 기존 180 유지.

## 검증
- `wscript.exe //B //NoLogo Run-Hidden.vbs -TrackActivity` 수동 실행 후 `tracker.log` 에 tick 기록 확인.
- 작업 스케줄러의 `ClaudeCodeMemoryTracker` 수동 실행 결과 `LastTaskResult=0`.
- 라이브 작업 스케줄러 액션이 두 작업 모두 `wscript.exe` 로 등록됐고 반복 주기가 각각 `PT1H30M`, `PT3H` 임을 확인.
- PowerShell AST parse 통과:
  - `Track-Schedule.ps1`
  - `Cleanup-Schedule.ps1`
  - `Test-Patterns.ps1`
- `Test-Patterns.ps1` 통과.
- `git diff --check` 통과.
