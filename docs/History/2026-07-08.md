# 2026-07-08 — Prevent Task Scheduler PowerShell Focus Theft

## Issue
- `ClaudeCodeMemoryTracker` ran every 30 minutes, and the PowerShell console briefly appeared, interrupting typing focus.
- Auto cleanup also directly ran `powershell.exe` in the same way, so the same issue could occur every 3 hours.

## Design Decision
- Not a temporary measure.
- The cause was not MemoryReset logic, but the Windows Task Scheduler invocation method that directly runs console host `powershell.exe` in the login session.
- Therefore, retained tracking/cleanup logic and changed only the scheduler entry point to a console-free `wscript.exe` wrapper, resolving the issue at its root cause.

## Changes
- Added `Run-Hidden.vbs`:
  - Calls `MemoryReset.ps1` in the same folder.
  - Uses `WScript.Shell.Run(..., 0, True)` to run PowerShell with its window hidden and pass through the exit code.
- `Track-Schedule.ps1`:
  - Changed `New-ScheduledTaskAction` executable from `powershell.exe` to `wscript.exe`.
  - Arguments: `//B //NoLogo "Run-Hidden.vbs" -TrackActivity`.
- `Cleanup-Schedule.ps1`:
  - Auto cleanup uses the same `wscript.exe` wrapper.
  - Arguments: `//B //NoLogo "Run-Hidden.vbs" -IdleOnly -SkipConfirmation -KeepAlive`.
- `Test-Patterns.ps1`:
  - Added a `Run-Hidden.vbs` existence check.
  - Added a regression check that tracker/cleanup schedule registration scripts use `wscript.exe` + `Run-Hidden.vbs`.
- Local runtime settings:
  - Changed `trackIntervalMin` in the git-excluded `tracker-settings.json` from 30 → 90.
  - Retained existing 180 for `idleMinutes`.
