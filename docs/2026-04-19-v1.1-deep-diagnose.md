# Work log — 2026-04-19 (v1.1.x: Deep + Diagnose)

> v1.0 (95%→31% memory recovery verification) plus v1.1 / v1.1.1 session record.

## Motivation

User feedback after v1.0 release:
- **Symptom**: Antigravity + Claude Code after restart, the PC is "less comfortable than a reboot"
- **Hypothesis**: accumulation of other caches (Memory Compression Store, kernel pool, GPU driver, explorer shell cache and others) not reclaimed by this script is the cause

Verification result: **hypothesis confirmed**. Beyond v1.0's 4 stages (working set / file cache / modified list / standby purge) many accumulated areas were confirmed.

## Features added (v1.1.0 → v1.1.1)

### Tier A — `-Deep` (safe, recommended)
- **Memory Compression Store flush**: `Disable-MMAgent -MemoryCompression` → 1500ms wait → `Enable-MMAgent`. Releases 1~3 GB accumulated.
- **System Working Set empty (NT level)**: `NtSetSystemInformation` command 2. Supplements protected processes skipped by the per-process loop due to insufficient `PROCESS_SET_QUOTA` permission in kernel mode
- **DNS / NetBIOS / ARP cache cleanup**: `Clear-DnsClientCache` / `nbtstat -R` / `netsh interface ip delete arpcache`

### Tier B — `-IncludeShell` (option, with flickering)
- **Explorer.exe restart**: Release 200~500 MB of shell cache. Rely only on Windows auto-restart (avoid elevation risk)
- **Windows Search service restart**: Release accumulated indexer memory

### `-Diagnose` mode (read-only, no UAC required)
- PerfCounter-based memory list distribution (Standby Cache by priority / Modified / Free & Zero / Cache)
- Memory Compression Store status
- Top 15 processes by memory usage (Working Set + Commit charge)
- Preview of termination target processes

### Tier C — **intentionally excluded**
Display adapter disable/enable (GPU memory reset). Reason:
- Risk of data loss during gaming/video editing/recording/streaming work
- Multi-monitor repositioning required
- Active DirectX/OpenGL apps may crash

Alternative: README guidance for the manual `Win+Ctrl+Shift+B` shortcut

## Multi-stage review results

### Round 1 (self-review) — 4 findings, all patched

| # | Severity | Issue | Patch |
|---|--------|------|------|
| 1 | P1 | After `Disable-MMAgent`, system compression stays permanently disabled if `Enable-MMAgent` fails | try/finally + dual-failure CRITICAL alert |
| 2 | P1 | Explorer restart 1500ms fixed wait (insufficient on systems with many shell extensions) | Polling loop introduced |
| 3 | P1 | At 95% memory state a compression flush can cause a decompress spike and OOM risk | skip if available RAM < 1024 MB |
| 4 | P2 | Ambiguous "Memory Compression" process info message | distinguish admin/build cases |

### Round 2 (independent agent review) — 4 additional P1 findings, 2 key items patched

| # | Severity | Issue | Decision |
|---|--------|------|------|
| 1 | P1 | PerfCounter English path fails on non-English Windows | **Keep** — measured operation confirmed (Vista+ auto mapping) |
| 2 | P1 | `Get-Process 'Memory Compression'` dead code | **Keep** — graceful fallback OK, message improvement only |
| 3 | P1 | Unclear relationship between NT command 2 and per-process loop | **Patch** — add comment |
| 4 | P1 | **Manual Explorer start runs in elevated context** → regular apps lack privileges | **Patch** — remove manual start, show user guide |

Additional applied:
- MMAgent decompress sleep 800ms → 1500ms (for GB-scale store)
- Clarified comment on supplementary effect of NT command 2

## Items not applied (intentional)

- **PerfCounter ID-based fallback**: added complexity vs measured normal operation → keep
- **Get-Process compression branch removal**: retain graceful fallback because it may work on some builds
- **Tier C (GPU adapter reset)**: Too risky
